## Phase Goal

**As a** chat user, **I want to** keep one conversation going in the browser page and start a fresh one when I choose, **so that** follow-ups and clarifying questions work where I chat and the project docs describe only what was built and measured.

<objective>
Make `rag/api/static/index.html` use conversations (PAGE-01, PAGE-02): hold the server's `conversation_id` (D-01), reset it on New conversation and on every change of the target documents (D-02 with the orchestrator's A2 and E10 resolutions), recover from a stale id with one automatic resend (D-03), show the conversation 409s as sentences and drop a superseded stream's late result with a new `AbortController` plus an epoch counter (D-04 refined), render a clarifying question as text (D-05, D-06) with existing styles only (D-12), and rewrite the one page test that states the opposite contract in the same commit (D-07 refined).

Purpose: ROADMAP Phase 5 criteria 1 to 3 in the page. The server already decides everything about conversations; the page holds one opaque string and drops it at the right moments, leaning on the server's 404 as the safety net (RESEARCH "Key insight").

Output: three commits: the tracer (id kept, New conversation, abort and epoch), the target-change resets with the rewritten test, then the stale-id retry, readable 409s and clarify rendering. The static contract test file and the node behaviour harness are plan 05-02 (tester after coder).
</objective>
