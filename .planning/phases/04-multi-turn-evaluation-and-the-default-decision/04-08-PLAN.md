## Phase Goal

**As a** system owner, **I want to** measure rewriting on and off against a multi-turn golden set, **so that** rewriting becomes the default only when it shows a gain outside the noise band and the numbers are recorded either way.

<objective>
Run the scored experiment on the frozen set with the live models: preflight Ollama and the tunnel, run the main qwen run with `--repeats 3 --answers`, run the gpt-oss retrieval-only comparison when the tunnel is up (D-10), confirm the regression arm, then append the rendered `## Results` to `docs/chat_memory_eval.md` below the untouched rule in a second commit (D-08), and record any arm that could not run as a STATE.md blocker (D-14).

Purpose: ROADMAP criteria 3 and 4: the run's numbers recorded in a committed file, and the default, the rewriter model and the question slot decided from them. The expected decision, because every row is pending human review, is "ships off (provisional: items pending human review)"; that is an acceptable outcome under the project's own rule (ROADMAP Planning Notes).

Output: one or two gitignored run folders, the Results commit, and a STATE.md blocker commit when an arm was skipped.
</objective>

## Flagged assumptions

- A4 (RESEARCH): rewriter calls take a few seconds and `--answers` with the vLLM generator takes on the order of 10 to 20 minutes with 4 workers; the plan allows a one-hour ceiling for the main run.
- A cold Ollama load took about 30.7 s in Phase 3 research and can make the first call time out; the llm_check right before the run warms the model, and one retry is allowed when the preflight still reports it unreachable.
- A5 (RESEARCH): `REMOTE_REASONING_EFFORT` is read when the vLLM client is constructed; the report records its value (`meta.reasoning_effort`) so a wrong effort is visible.
