## Decision recorded: naive style forwards the block

`naive` forwards `history_block` like `standard` and `spotlight`. RESEARCH A6 and PATTERNS.md recommend forwarding; `.planning/research/ARCHITECTURE.md` line 178 says naive ignores it. Forwarding wins because silently dropping a non-empty block is a trap for whoever calls `build_prompts` with `style="naive"`, the naive user prompt already comes from `build_user_prompt`, and the identity and position tests in plan 01-04 then cover all three styles the same way. Reversible: one argument in one branch.

<assumption_delta_decision>
Detector: `assumption-delta scan 1` reported `detected: true` (pluralization cue "also", from the ROADMAP scope note). Identity question: does the noun that identifies a prompt still name the right thing once a prompt can carry history?
- Primary noun: the exact user-prompt bytes (the LLM cache keys on the full prompt; the golden results were measured on those bytes).
- Decision: no-change. History is an optional segment inside the same byte string, not a second identity next to it. An empty block yields today's bytes (so every existing cache key and golden result still applies), and a non-empty block yields a different byte string and therefore a different cache key, which is correct.
- Invariant test (accepted, already planned): plan 01-04's `test_empty_history_equals_no_history_equals_snapshot` goes red the moment an empty history changes the bytes.
</assumption_delta_decision>
