## Phase Goal

**As a** chat user, **I want to** ask a follow-up inside a conversation that the server remembers for me, **so that** the answer uses my earlier turns while my history stays private to me, disappears with its document, and fits the model's context window.

<objective>
Wire the conversation store (plan 02-03) and the history helpers (Phase 1 plus plan 02-02) into the request path: the `conversation_id` field and the three status mappings in `rag/api/main.py`, and in `rag/api/service.py` the lookup, lease, caps, history block, turn persistence and the delete cascade (D-04 to D-18).

Purpose: this is where every requirement of the phase becomes observable through the four ask routes. RESEARCH "Primary recommendation": put every conversation check inside `_retrieve`, in a fixed order, so every failure is an HTTP status before the first SSE byte; read turns only after the lease; persist, then release, then yield `final`.

Output: edits to `rag/api/service.py` and `rag/api/main.py` (this is the only plan that edits `service.py`). The route and service tests are plans 02-05 to 02-08 (coder before tester); this plan verifies with end-to-end one-line checks through `TestClient` and the existing suites.
</objective>

## Decisions recorded in this plan

- **D-04 refined (orchestrator resolution of RESEARCH Open Question 6):** `max_length=512` instead of 64. A refinement, not a reversal: the field stays an optional string and the store still decides the 32-hex shape, but every plausible malformed id (traversal strings, junk up to 512 characters, upper case, trailing newline) now gets CONV-02's single 404 body. Above 512 characters the request is a 422, the documented limit; plan 02-05 pins both sides.
- **Open Question 7 (orchestrator resolution):** the prompt-budget check runs only when the history block is non-empty, so a first turn behaves exactly as today; the turn and word cap check still runs on every turn of an existing conversation.
- **Open Question 8 (orchestrator resolution):** duplicate declared `doc_ids` are removed before the location and scope key are chosen; implemented in `scope_of` (plan 02-03), relied on here.
- **The stored answer** is `result["answer"]` from `_describe`, which is `trace.answer`: the post-filter text for ordinary answers and the stream guard's verdict for streams (the withheld notice when blocked). `usage["raw_answer"]` is never stored (RESEARCH "Don't Hand-Roll").
- **Where `conversation_id` and `turn` go in `_describe`** (Claude's discretion): right after `"query_id"`.
- **`_remember` failures:** a `FileNotFoundError` race is a dropped write inside the store (the answer is still returned, D-03); any other `OSError` propagates, so the ordinary route answers 502 and the stream sends its `error` event; nothing is swallowed. Rated reversible.
- **`test_the_streamed_response_equals_the_ordinary_one` needs no edit** (RESEARCH Pitfall 10, orchestrator correction): it compares a fixed key tuple. D-06's clause asking to update it and STATE.md's note are superseded; plan 02-06 adds the different-ids assertion and plan 02-09 updates STATE.md.
