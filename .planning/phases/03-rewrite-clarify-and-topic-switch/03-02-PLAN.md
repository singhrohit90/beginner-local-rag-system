## Phase Goal

**As a** chat user, **I want to** ask a follow-up with a pronoun and have it turned into a standalone question before retrieval (or get one clarifying question when it is ambiguous), **so that** retrieval finds the passages the full phrasing would find.

<objective>
Extend the Phase 2 conversation module so a stored turn can say it was a clarification (D-12) or the start of a new topic (D-14), and add the pure cut `since_topic_start` that both the rewrite window and the answer-prompt history start from.

Purpose: RWR-03 (a clarification is stored with its kind, which is how "never two in a row" is decided, D-13) and RWR-04 (a topic switch starts a clean history). The keys appear only when non-default, so every Phase 2 exact-key assertion stays true with the switch off (RESEARCH Pattern 2, Pitfall 1).

Output: two small edits to `rag/api/conversations.py`, two commits. This is the only plan that edits the file.
</objective>

## Decisions recorded in this plan

- **Only non-default keys are stored** (orchestrator rule, RESEARCH A9): `kind` only for `"clarify"`, `topic_start` only when true. A uniform key set would need a coordinated edit of the Phase 2 exact-key tests, which this phase does not make.
- **Assumption-delta checkpoint (advisory, detector fired on "second"):** the noun "turn" now has two kinds (answer, clarify). Decision: add-alongside, accepted as debt: the optional `kind` key with default `"answer"` sits beside the Phase 2 shape so Phase 2's seven-key assertions stay true. A promote (every turn always carries `kind`) becomes necessary when the page or a reload view must render a stored clarification differently (Phase 5, PAGE-02, or v2 reload-resume); that change would update the Phase 2 key-set tests in the same commit.
- **`since_topic_start` lives here, not in rag/query/history.py:** it reads stored dicts, not `HistoryTurn`, and `window()` must keep accepting plain items (Phase 1 verify).
