## Phase Goal

**As a** chat user, **I want to** ask a follow-up with a pronoun and have it turned into a standalone question before retrieval (or get one clarifying question when it is ambiguous), **so that** retrieval finds the passages the full phrasing would find.

<objective>

Purpose: this is where RWR-01 to RWR-04 become observable through the four ask routes. RESEARCH Pattern 1: every decision is made in `_retrieve`, before any SSE byte; the rewrite result is data, never an exception.

</objective>

## Decisions recorded in this plan

- **D-09 (D2 resolved, Option A):** fail-open with a visible flag. RWR-02's text says "any rewrite error surfaces as an HTTP status before any SSE byte"; D2 was resolved in discuss-phase as a visible `fallback` status decided in `_retrieve` before any SSE byte, which ROADMAP Phase 3 criterion 3 allows ("an HTTP status before any SSE byte, or a flagged fall-back to the raw message"). Rated costly (see Task 1): switching to fail-closed later changes the error contract of four routes and the page.
- **`rewrite=True` without a rewriter (orchestrator resolution):** `ValueError` at construction, never a silent default to the reasoning generator.
- **A11 (orchestrator resolution):** `rejected_question` is stored in `trace.config["conversation"]` when a guard rejects a rewrite; traces are saved only for single-document questions inside the document folder, so a delete removes it; it never reaches the response.
- **Clarify on the stream (correction of RESEARCH Code Example 8):** the stream route's `frames()` calls `events.close()` in its `finally` (rag/api/main.py line 349), and a list iterator has no `close()`, so the clarify branch returns a one-event generator, not `iter([...])`.
- **D-12 "after filter_output":** the clarifying text is vetted inside `rewrite_question` (flagged, too_long, invented_detail) and `_clarify_response` still passes it through `filter_output(text, "")`, so the shown text and `blocked` follow the same filter as every other answer.
- **Second model role (assumption-delta, advisory):** `llm` still names the answer model; the rewriter is a separate role, `rewrite_llm`, not a second instance of the same need. Decision: no-change to `llm`'s identity.
- **D-11:** the answer prompt's question slot is the effective question in this phase (mechanically: `Trace.question`); the history block is unchanged. Phase 4 measures the alternative.
